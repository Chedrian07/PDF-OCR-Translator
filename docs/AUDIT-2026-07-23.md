## 범위와 결론

저장소 루트의 로컬 `baidu/Unlimited-OCR` Metal/CUDA 실행 경로, OCR SSE 라이브
스트림, 번역 레이아웃 PDF 내보내기를 코드·테스트·실환경으로 교차 점검했다.

- **Metal 로컬 OCR**: M4 Max에서 원격 추론 API 없이 실모델 변환 성공.
- **CUDA 구성**: 이 호스트에는 NVIDIA GPU가 없어 런타임 추론은 불가했지만,
  compose 해석·cu129 lock·GPU reservation·보안 바인딩을 검증했다.
- **SSE**: 연결 전/재연결 중 생성된 OCR token도 replay로 무손실 복구한다.
- **PDF**: 번역문 조판 실패가 원문 유실로 이어지지 않고, 텍스트 리댁션이
  이미지·벡터 그래픽을 제거하지 않는다. 구조가 같은 표는 셀별 번역한다.
- **실번역 통합**: 루트 `.env`의 OpenAI 호환 API로 영문 2페이지 15/15 유닛을
  실제 번역하고 같은 잡에서 PDF까지 생성했다.
- **회귀 게이트**: 백엔드·프런트·sidecar·native·실브라우저 E2E가 녹색이다.

## 이번 수정

### 1. OCR token replay

기존 EventBroker는 구독자가 연결되기 전에 발행된 token을 보관하지 않았다. 업로드
응답과 EventSource 연결 사이 또는 네트워크 재연결 동안 RAW 출력·박스·라이브
미리보기의 일부가 유실될 수 있었다.

- 실행 중 잡별 token 히스토리를 최대 8MiB 보관한다.
- 구독 등록과 replay 스냅샷을 같은 락에서 수행해 경계 token을 replay/신규 token
  중 정확히 한 번 전달한다.
- `done`/`error`에서 히스토리를 즉시 폐기한다.
- 프런트는 replay 원문으로 RAW·grounding boxes·증분 preview를 함께 재구축한다.
- 상한 초과(`truncated:true`) 시 불완전 replay는 적용하지 않고 완료 산출물을 쓴다.

### 2. 번역 PDF 무손실 가드

- 원문/번역 레이아웃의 페이지·블록 수 및 `type`/`bbox`/`image` 대응을 전체 문서
  수정 전에 검증한다. 구조 불일치 시 잘못된 사각형을 리댁션하지 않고 중단한다.
- PyMuPDF Shape로 축소 조판을 dry-run한 뒤 들어가는 블록만 리댁션한다. 최소
  크기에도 들어가지 않으면 원문을 보존하고 warning을 남긴다.
- `apply_redactions(images=NONE, graphics=NONE, text=REMOVE)`를 명시해 같은 블록의
  그림·밑줄·차트 선을 보존한다.
- PDF 요청 자체가 원본 텍스트 레이어의 실측 폰트 크기·세로쓰기 메타를 추출한다.
  레이아웃 탭을 먼저 열었는지에 따라 내보내기 품질이 달라지지 않는다.

### 3. FakeEngine E2E 폐쇄

FakeEngine 결과에 수식 샘플이 없어 실브라우저 KaTeX assertion 하나가 항상
실패하던 기존 한계를 제거했다. 데모 Markdown에 `\\( E = mc^2 \\)`를 추가하고
서버 렌더 회귀 assertion으로 고정했다.

### 4. 후속 항목 3-5 구현

- **전문 조판 3A**: 행·열이 같은 HTML 표를 최대 500셀까지 셀별 교체하고 원본
  벡터 격자를 보존한다. 일반 텍스트 속 단순 LaTeX 위첨자는 `mc²`처럼 평문화한다.
- **충돌 회피 4A**: 번역문이 원래 bbox에 안 들어가면 같은 단의 다음 블록·표·

  개수를 전달하고 브라우저 다운로드 뒤 토스트로 표시한다.
- **브라우저 E2E 5A**: 외부 호출 없는 mock OpenAI 번역과 테스트 전용 OpenAI

## 남은 한계와 다음 우선순위

1. 이 Mac에서는 CUDA 실추론을 주장할 수 없다. NVIDIA/Blackwell 호스트에서 위
   smoke와 실제 논문 코퍼스 벤치마크를 다시 실행해야 한다.
2. 독립 equation 블록과 세로쓰기는 아직 원본 보존이다. 다음 단계는 벡터 수식
   조판기와 CJK 세로쓰기 배치기이며, 실패 시 원본 보존 불변식은 유지한다.
3. 현재 충돌 회피는 같은 단의 아래 빈 영역만 사용한다. 좌우/다단 재배치는 읽기
   순서를 바꿀 수 있어 미리보기와 사용자 승인을 포함한 별도 단계로 진행한다.
4. CUDA 실추론은 NVIDIA 장비에서만 남아 있다. Q&A/번역의 Ollama 방식은 사용자
   지시에 따라 검증 대상에서 제외한다.
