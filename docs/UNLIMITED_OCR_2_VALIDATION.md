# Unlimited-OCR-2 잔여 개발 재검증

검증일: 2026-10-31. 비교 기준: `cc97954`의 기존 모델, 이전 전환: `976a588`.

**합의된 개발·검증 범위의 잔여 항목을 마쳤다.** 표준 CUDA 실행, 품질 비퇴행, 전체 회귀, 실제 번역 공급자를 통한 브라우저 E2E 및 번역본 내보내기를 검증했다. Apple Silicon GPU 실기기 검증은 사용자 측에서 진행하기로 한 범위다.

이전 날짜의 입력·기준 결과는 수정하지 않았다. [2026-10-30 기록](https://github.com/Chedrian07/PDF-OCR-Translator/blob/976a588b7edc9f0b2e7712ab65b8580fa84897d2/docs/UNLIMITED_OCR_2_VALIDATION.md)과 [고정 평가셋](../benchmark_docs/unlimited2/README.md)을 함께 볼 수 있다.

## 수정한 잔여 항목

- 표준 `docker compose --profile cuda`의 `gpus: all` 경로로 실제 추론 성공. 드라이버 경로 지정·WSL 장치 수동 연결을 사용하지 않았다.
- 매 요청의 합성 추론 health 호출을 `/ready`로 교체했다. 모델 snapshot·runtime 버전과 실제 scheduler 응답은 매번 확인한다. 준비 확인 중앙값은 1.028초에서 0.023초로 감소했다.
- 보수적인 수식 문법 파서로 누락된 구분자를 복원한다. 코드·URL·HTML 속성·기존 수식·불명확한 문장은 보존하고, 원 모델 출력도 별도 보존한다. 저장·스트림·레이아웃이 같은 규칙을 사용한다.
- 흰 종이가 대부분이고 잉크의 black point가 올라간 입력에만 낮은 쪽 1% 명암 확장을 적용한다. 크기·좌표·원본 페이지·그림 크롭은 바꾸지 않으며, 상단 밝기 절단이나 이진화를 하지 않는다. 이 평가셋에서는 scan 한 페이지만 선택됐다.
- 네 변의 명확한 픽셀 근거가 있는 직사각형 그림만 경계를 정제한다. 모호한 경우 기존 상자를 유지하고, 변경된 크롭과 최종 레이아웃 좌표는 일치시킨다.
- 얕은 CJK 상자는 글꼴 전체 윤곽의 안전한 범위를 사용하되 기존 축소 하한과 PDF span 충돌 검사를 유지한다. 변경 전부터 실패하던 Malgun Gothic 검사도 통과했다.

## 실제 CUDA 성능

동일 RTX 5070 Ti, 고정 PDF·원본 래스터, 200 DPI, BF16, 동시성 1, 청크 8쪽. 양자화·해상도 축소 없음. 준비 실행 1회 후 3회 중앙값이다. 모델 입력의 명암 보정 여부와 원본/입력 픽셀 해시는 각 측정 JSON에 남겼다.

첫 텍스트는 클라이언트가 받은 최초 텍스트 델타이며 네트워크·이미지 준비·디코딩 버퍼를 포함한다. GPU 전체 VRAM을 100ms 간격으로 표본 측정했으며 데스크톱 사용량도 포함한다.

## 품질 비교

| 문서 | CER 기존 → 최종 | 그림 수 기존 → 최종 / 정답 | 수식 조판 표식 기존 → 최종 | 그림 평균 IoU 기존 → 최종 |
|---|---|---|---|---|
| en-mixed | 0.00% → 0.00% | 2 → 2 / 2 | 1 → 1 | 0.9805 → 0.9982 |
| ko-report | 6.67% → 6.67% | 1 → 1 / 1 | 1 → 1 | 0.9632 → 0.9822 |
| scan | 6.67% → 6.67% | 1 → 1 / 1 | 1 → 1 | 미주석/해당 없음 |
| columns | 0.00% → 0.00% | 0 → 0 / 0 | 0 → 0 | 미주석/해당 없음 |
| long-32 | 5.36% → 0.00% | 22 → 32 / 32 | 15 → 16 | 0.6735 → 0.9982 |

측정한 CER·그림 수/IoU·표 구조·읽기 순서 지표의 비퇴행을 확인했다. 모든 후보의 페이지 마커·그림 수가 입력과 일치했다. 다단 읽기 순서 표식 16/16개, 쌍 순서 정확도 1.0이다.

추가 SHA256 결합 주석은 각 표 셀과 식의 연산자까지 검사한다. 영문/한글/스캔 표는 12/12 셀, 장문 표는 기존 180/192에서 최종 192/192로 개선됐다. 영어 식은 1/1, 장문 식은 16/16, 스캔 식은 기존 0/1에서 최종 1/1 전사 일치다. **깨끗한 한글 문서의 식은 두 모델 모두 0/1로 남는다.** 이는 기존 대비 퇴행은 아니지만 절대 인식 오류이며 결과를 완벽한 수식 인식으로 해석하면 안 된다.

CER은 공백·구두점과 일부 LaTeX wrapper를 정규화한 진단 지표다. 원본 도형 안 글자도 참조에 포함돼 그림으로 보존한 글자는 문자 누락으로 계산된다. 식 전사 일치는 연산자를 보존한 토큰 비교이며 일반적인 수학 의미 동치 판정이 아니다. 고정 한국어 생성 문서에는 오른쪽 페이지 밖으로 넘친 줄도 있어 그 입력·참조는 동결 상태로 유지했다.

## 회귀 및 플랫폼

- 백엔드 전체: **2,338 통과, 34 건너뜀, 실패 0**. 이전 CJK 실패는 수정됐다.
- 프론트엔드 단위: **382 통과**. 실제 OCR + 모의 번역/Q&A 전체 브라우저 E2E: **전부 통과**. 업로드·SSE·결과·번역 UI·HTML/PDF 다운로드·취소/오류 복구 시나리오를 포함한다.
- 실제 공급자 전용 브라우저 하네스: **전부 통과, mock_provider=false**. 업로드·실제 OCR 스트림·미리보기·실제 한국어 번역·번역 화면·원본/번역 HTML·Markdown·ZIP·PDF를 검증했다. 12/12 유닛을 새로 번역했으며 PDF 2쪽, 수식·그림·표 구조와 독립형 HTML도 확인했다.
- 사용자 인증 설정 갱신 후 확인된 공급자 호환 문제 두 가지를 수정했다. 명시적으로 거절된 `temperature`는 한 번만 생략 재시도하고, Responses 문자열 축약 입력 거절에는 동일한 내용을 정식 메시지 배열로 한 번만 재시도한다. 모델·공급자·추론 설정은 바꾸지 않는다. 실제 적용 여부와 고정 안내를 번역 상태/리포트에 기록한다. 일반400과 반복 거절은 무한 재시도하지 않는다. 초기401 및 중간400은 과거 진단 기록이며 최종 실서비스 E2E는 성공했다.
- CPU: 호스트와 최종 Docker 이미지에서 새 명암 보정 대상 이미지로 실제 고정 모델 추론 `Hello OCR 2` 성공.
- CUDA: 우회 없는 표준 Compose에서 실제 스캔 추론·레이아웃·KaTeX 표시 성공. 12쪽 문서 창 추론의 첫 출력 후 약29ms에 취소됐고, 작은 페이지 출력 제한을 오류로 감지했다. 그 뒤 정상 문서 출력은 취소 전 독립 요청과 바이트까지 일치했다.
- MLX: Linux MLX CPU에서 torch와 SR-SWA 수치 패리티 통과, 실제 활성 파라미터 691개 strict 로딩 확인. 전처리의 CPU/MLX 픽셀 패리티도 통과했다.
- Apple MLX/Metal GPU 실기기 검증은 사용자 측 항목이다.
- 실모델 CI는 수동 입력 `run_real_ocr=true`와 준비된 `ocr-gpu` 전용 러너를 요구하도록 수정했다. 일반 CI는 모델 없이 실행된다. CI 계약 검사62개 및 삽입 스크립트 문법 검사가 통과했다.
- Ruff, Compose 구성, 고정 lock 검사 통과. 시스템 드라이버·사용자 `.env`는 수정하지 않았다.

## 재현

```bash
docker compose --profile cuda up -d --build unlimited-ocr2 ocr-cuda
DISABLE_DOTENV=1 backend/.venv/bin/pytest backend/tests --disable-warnings --tb=short
npm --prefix frontend test
# 실제 OCR + 모의 번역/Q&A 전체 흐름:
E2E_OCR_ENGINE=unlimited2 E2E_OCR_DEVICE=cuda OCR_SIDECAR_URL=<reachable-sglang-url> \
  npm --prefix frontend run test:e2e-mock
# 실제 설정된 번역 공급자까지 사용 (인증/설정 오류는 별도 exit 2):
OCR_SIDECAR_URL=<reachable-sglang-url> npm --prefix frontend run test:e2e-live
```

명시적인 검증 명령에서 `--env-file /dev/null`을 사용한 이유는 사용자 자격증명을 배포 로그·검증 환경으로 복사하지 않기 위해서다. 모델 포트는 Compose 내부 전용이다. 호스트에서 직접 검증할 때는 로컬 SGLang 주소 또는 해당 호스트에서 접근 가능한 컨테이너 주소를 지정한다.

## 원격 CI 추적 및 수정

첫 push `2460a02`의 원격 CI에서 프론트엔드의 오래된 모델명 기대값2개와 새 보안 권고를
확인했다. 앞서 프론트엔드381개가 통과했다고 기록한 것은 잘못이었다. 당시 로그는
379통과/2실패였으며 이를 확인하지 못했다. 기대값과 명시적 모델-ID/fallback 검사를
수정한 최종 프론트엔드 검사는382개 모두 통과했다.

의존성은 Pillow13.0.0, certifi2026.10.23, filelock4.2.4, setuptools84.2.1만 제한적으로
갱신했다. torch/transformers/모델은 바꾸지 않았다. 원본5종의 모델 입력 픽셀 해시는 갱신 전과
모두 같았고 실제 CUDA3회 측정·품질 검사·실제 공급자 번역 E2E도 다시 통과했다.
최종 감사는 백엔드의 기존 수용12건과 미사용 DiskCache의 한정된 수용 별칭2건을 제외하고
실패 권고가 없다. 이는 취약점0개 선언이 아니며, DiskCache 수용은2026-11-30에 만료된다.
정확한 검토 wheel버전/SHA·경로 차단·캐시 소유권·strict 감사 내용은
[운영 문서](UNLIMITED_OCR_2.md#dependency-audit)와 정책 파일에 기록했다.
